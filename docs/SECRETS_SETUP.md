# GitHub Secrets Setup Guide

This guide explains how to properly set up the required GitHub Secrets for the APT repository to work with GPG signing.

## Required Secrets

The repository needs three secrets for GPG signing:

1. **GPG_PRIVATE_KEY** - Base64-encoded private GPG key
2. **GPG_KEY_ID** - The 40-character GPG key ID
3. **GPG_PASSPHRASE** - The passphrase for the GPG key (can be empty if no passphrase)

## Step-by-Step Setup

### 1. Generate GPG Key (if you don't have one)

```bash
gpg --full-generate-key
```

Follow the prompts:
- Select: **(1) RSA and RSA**
- Key size: **4096**
- Expiration: **2y** (2 years recommended)
- Real name: **Certy APT Repository**
- Email: **your-email@example.com**
- Passphrase: Enter a secure passphrase (or leave empty for no passphrase)

### 2. Get Your GPG Key ID

```bash
# List your keys
gpg --list-keys --keyid-format LONG

# Output will look like:
# pub   rsa4096/ABCDEF1234567890 2025-10-14 [SC] [expires: 2027-10-14]
#       ABCDEF1234567890ABCDEF1234567890ABCDEF12  <-- This is your key ID
# uid                 [ultimate] Certy APT Repository <your-email@example.com>
```

The 40-character string is your **GPG_KEY_ID**.

### 3. Export Private Key and Base64 Encode

```bash
# Export the private key (replace YOUR_KEY_ID with your actual key ID)
gpg --armor --export-secret-keys YOUR_KEY_ID > private-key.asc

# View the file to ensure it exported correctly
cat private-key.asc
# Should start with: -----BEGIN PGP PRIVATE KEY BLOCK-----

# Base64 encode the private key for GitHub Secrets
base64 -w 0 private-key.asc > private-key-base64.txt

# Or on macOS:
base64 -i private-key.asc -o private-key-base64.txt

# View the base64 encoded content
cat private-key-base64.txt
```

**Important**: The base64 file should be a single long line with no line breaks!

### 4. Add Secrets to GitHub

1. Go to your repository on GitHub: `https://github.com/YOUR_USERNAME/certy-apt`
2. Click **Settings** → **Secrets and variables** → **Actions**
3. Click **New repository secret**

#### Add GPG_PRIVATE_KEY

- **Name**: `GPG_PRIVATE_KEY`
- **Value**: Copy and paste the **entire contents** of `private-key-base64.txt`
- Click **Add secret**

#### Add GPG_KEY_ID

- **Name**: `GPG_KEY_ID`
- **Value**: Your 40-character key ID (e.g., `ABCDEF1234567890ABCDEF1234567890ABCDEF12`)
- Click **Add secret**

#### Add GPG_PASSPHRASE

- **Name**: `GPG_PASSPHRASE`
- **Value**: Your GPG key passphrase
  - **IMPORTANT**: You MUST add this secret even if your key has no passphrase!
  - If you didn't set a passphrase, add the secret but leave the value **empty** (blank)
  - The workflow requires this secret to exist for non-interactive GPG operations
- Click **Add secret**

### 5. Export Public Key (for users)

```bash
# Export public key
gpg --armor --export YOUR_KEY_ID > KEY.gpg

# This file will be automatically generated by the workflow
# and published at: https://YOUR_USERNAME.github.io/certy-apt/KEY.gpg
```

## Verification

### Test GPG Import Locally

Before adding to GitHub, test that your base64-encoded key works:

```bash
# Test decoding and importing
cat private-key-base64.txt | base64 -d | gpg --import --dry-run

# Should show: "secret key imported" or similar
```

### Common Issues and Solutions

#### Issue: "base64: invalid input"

**Problem**: The base64 file contains line breaks or invalid characters.

**Solution**:
```bash
# Re-encode without line breaks
# On Linux:
base64 -w 0 private-key.asc > private-key-base64.txt

# On macOS:
base64 -i private-key.asc | tr -d '\n' > private-key-base64.txt

# Verify it's a single line
wc -l private-key-base64.txt
# Should output: 0 (zero lines)
```

#### Issue: "no valid OpenPGP data found"

**Problem**: The secret value in GitHub is empty or corrupted.

**Solution**:
1. Delete the secret in GitHub Settings
2. Re-export and re-encode the key
3. Copy the **entire** base64 string
4. Add the secret again, ensuring no whitespace is added

#### Issue: "gpg: signing failed: Bad passphrase"

**Problem**: The GPG_PASSPHRASE secret is incorrect or missing.

**Solution**:
1. Verify your passphrase is correct locally: `echo "test" | gpg --clearsign`
2. Update the GPG_PASSPHRASE secret with the correct passphrase
3. If you have no passphrase, set the secret to an empty value

#### Issue: "gpg: signing failed: No secret key"

**Problem**: The GPG_KEY_ID doesn't match the imported key.

**Solution**:
1. Verify the key ID: `gpg --list-secret-keys --keyid-format LONG`
2. Ensure you're using the 40-character long format, not the short format
3. Update the GPG_KEY_ID secret with the correct ID

## Security Best Practices

### 1. Secure Your Private Key

```bash
# After adding to GitHub, securely delete local files
shred -u private-key.asc private-key-base64.txt

# Or on macOS:
rm -P private-key.asc private-key-base64.txt
```

### 2. Use Key Expiration

Set your GPG key to expire and renew it periodically:

```bash
# Edit key to set expiration
gpg --edit-key YOUR_KEY_ID
# At gpg> prompt:
expire
# Follow prompts, then:
save
```

### 3. Backup Your Keys

Keep an **encrypted backup** of your GPG keys in a secure location (not in the repository!).

### 4. Rotate Secrets Regularly

1. Generate a new GPG key annually
2. Update GitHub Secrets
3. Revoke the old key
4. Publish the new public key

## Optional: Testing Without GPG Signing

If you want to test the repository without GPG signing first:

### Option 1: Skip Signing (Workflow will handle this)

The workflow now gracefully skips signing if secrets are not set. Simply don't add the secrets and the repository will be published unsigned.

### Option 2: Use Dummy Secrets for Testing

**NOT RECOMMENDED FOR PRODUCTION**

You can add placeholder secrets to test the workflow:
- GPG_PRIVATE_KEY: `test` (will fail but you'll see different errors)
- GPG_KEY_ID: `0000000000000000000000000000000000000000`
- GPG_PASSPHRASE: (empty)

The workflow will skip signing if keys are invalid.

## Verifying Setup

After adding secrets, run the workflow:

1. Go to **Actions** tab
2. Select **Build and Publish APT Repository**
3. Click **Run workflow**
4. Enter a version (e.g., `v1.1.0`)
5. Click **Run workflow**

Check the logs for:
- ✅ "GPG key imported successfully"
- ✅ "Public key exported successfully"
- ❌ "Warning: GPG key not found" (secrets not set correctly)

## Quick Reference Commands

```bash
# Generate key
gpg --full-generate-key

# List keys (get key ID)
gpg --list-keys --keyid-format LONG

# Export and encode private key
gpg --armor --export-secret-keys YOUR_KEY_ID | base64 -w 0 > private-key-base64.txt

# Export public key
gpg --armor --export YOUR_KEY_ID > KEY.gpg

# Test import
echo "YOUR_BASE64_STRING" | base64 -d | gpg --import --dry-run

# Verify key
gpg --list-secret-keys
```

If you continue to have issues:

1. **Check the workflow logs** in GitHub Actions

3. **Test locally** using the commands above
4. **Open an issue** with the error message (don't include private keys!)
